# When a prototype becomes critical, does your GitHub policy know? (Sponsored)

**Thu Oct 29 2026, 9:35 AM–9:50 AM PDT** · [Silent Disco Demos](../rooms/silent-disco-demos-festival-pavilion.yaml)

**Speakers:** [Baruch Sadogursky](../people/baruch-sadogursky.md)

**Hosted by:** [Port](../organizations/port.md)

What happens when a prototype goes into production and starts handling real customer payments, but its GitHub repository still carries the merge requirements it launched with? 

In this session, Baruch Sadogursky shares how he syncs ownership and business criticality from Port into GitHub as custom properties, making it possible to find repositories by owning team and point a GitHub ruleset at critical services. 

You'll watch that gap close live, and leave with a repeatable pattern: Port supplies the context, and GitHub turns that context into enforced policy.

- **Type:** Product Demo
- **Track:** Build software, not code
- **Level:** Level 100: Introductory
- **Topics:** Agile practices, Automated Infrastructure Deployment, Continuous Integration + Continuous Deployment (CI/CD), DevOps and DevSecOps, Infrastructure as code, Platform engineering, Code quality, review, and completion, Governance and compliance, AI: Agents, AI: MCP and other integrations
- **GitHub products:** Actions, GitHub Copilot
- **Audience:** Enterprise - Engineering Leadership, Enterprise - Developer, Security Professional, Startups, Security Leadership
