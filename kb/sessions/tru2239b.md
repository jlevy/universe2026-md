# Your agents write the fix. Observability supplies the context. (Sponsored)

**Thu Oct 29 2026, 10:00 AM–10:40 AM PDT** · [Silent Disco Breakouts](../rooms/silent-disco-breakouts-festival-pavilion.yaml)

**Speakers:** [Andrew Norris](../people/andrew-norris.md), [Michael Beemer](../people/michael-beemer.md)

**Hosted by:** [Dynatrace](../organizations/dynatrace.md)

Your agent’s pull request passed CI and merged. But will the fix hold up under real traffic? In this live demo, you’ll see Bluebox by Dynatrace use OpenTelemetry data to brief a coding agent on a microservice app. When the app breaks, the agent opens a pull request with an evidence-backed diagnosis and proposed fix. After review and deployment, the team checks error rates and SLOs for regressions. You’ll leave with a practical model for verifying agent-written changes and deciding where human review, escalation, and a kill switch belong.

- **Type:** Breakout Session
- **Track:** Trust every commit
- **Level:** Level 200: Intermediate
- **Topics:** Agile practices, Monitoring and observability, Collaboration, Code quality, review, and completion, AI: Agents, AI: MCP and other integrations, Developer experience (DX)
- **GitHub products:** Codespaces, GitHub Copilot, GitHub Enterprise Cloud, VS Code
- **Audience:** Enterprise - Engineering Leadership, Enterprise - Developer, Startups
- **Mentions:** [OpenTelemetry](../software/opentelemetry.yaml)
