  - text: Lights out (dark) factories or lights on factories? There’s a misconception that the goal with
      agents is full lights-out. Code written, tested, deployed, maintained... no humans needed. I don't
      have that same desire for it. We run a lights-out operation at Swamp for ops and reactive work.
      Alerts come in, the system figures out what’s going on, handles it or escalates. That works because
      we’ve already done the thinking about what should happen. The system knows where to stop. Product
      work though? A small team build Swamp, none of us write code, and we’re still arguing about what
      to build and how it should work. Not reviewing diffs. Arguing about whether a feature belongs, whether
      the approach is right, whether we’ve thought about what happens when a user hits the edge we didn’t
      plan for. That taste is what we care about greatly! This is why I don't want to push toward full
      autonomy. A ticket like “add a retry command” looks ready to go. Then you start asking whether retry
      means restart from scratch or resume from the failure, what happens to infrastructure the first
      run created, whether the workflow definition might have changed since. At agent speed those questions
      just become code, nobody discussed them but they shipped. I want agents doing the work. I don’t
      want to find out what we promised users by reading the docs after it’s built. https://lnkd.in/e-TMkFd8
